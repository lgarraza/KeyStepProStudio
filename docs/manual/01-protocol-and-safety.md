# Protocol and device rules

- Target: KeyStep Pro firmware **2.5.20** (build 2085), official firmware only. Any other version opens read-only
  (`ksp::Identity::isKnownFirmware`, `Device::canWrite`).
- The SysEx protocol is Arturia's undocumented one, mapped by KSCON (MIT). Frames, commands and quirks:
  [`../protocolo.md`](../protocolo.md). Source of truth for values: `Source/Ksp/RecallPlan.h` (generated by
  `Tools/gen_from_kscon.py`, never edited by hand).
- Reads show **flash**, not live state: a project edited on the device but not saved is invisible. The app is a
  librarian: read, edit, write.
- A read session is per project: open (cmd 0x05), bulk GETs (0x0B), one at a time (~4 ms each, 8951 per project).
  A write is open, bulk SETs (0x0C), commit (0x06, ~3 s, reloads the project).
- Commit flips every pattern/scene state that was not sent, so a write always sends all of them, last
  (`writePlan`). Values >= 0xF7 cut replies short (re-read one by one); they cannot be written either.

## Rules that protect the KeyStep

1. Writes only through `Device::writeSlot`: firmware 2.5.20, frames for one slot only (`isWriteFor`), and only right
   after `backupSlot` saved that slot to `Documents/KeyStepPro Studio/Backups/ksp-pre-restore-P<slot>-<date>.json`.
2. Every write is read back and compared value by value.
3. A firmware other than 2.5.20 opens read-only: the app shows "not tested: read only" in the sync bar and `Device::writeSlot` refuses. The app stays behind Arturia's releases until a new one is tested (Leo, 2026-10-30).
4. The Studio app offers all 16 slots (working memory; Leo, 2026-10-30). Every write confirms, backs the slot up first and reads it back. Global settings are not written.
5. MIDI Control Center must be closed (the port is exclusive on Windows).
6. Read-only tools are limited by `isReadOnlyRequest`.
